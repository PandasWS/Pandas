# 提交规范

Pandas 新编写的提交信息采用 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/zh-hans/v1.0.0/)。从上游导入的历史提交保留原信息。

## 格式

```text
<type>[可选 scope][可选 !]: <描述>

[可选正文]

[可选 footer]
```

标题使用简洁、具体的中文描述，保留技术标识符；类型和可选范围使用英文。冒号后留一个空格。

**第一行标题末尾禁止使用英文句号 `.` 或中文句号 `。`。** 这是 Pandas 的附加约定。正文和 footer 可以使用正常标点。

| type | 用途 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 修复已有行为 |
| `docs` | 文档调整 |
| `refactor` | 保持外部行为的结构调整 |
| `perf` | 性能优化 |
| `test` | 测试和验证用例 |
| `build` | 构建系统或构建依赖 |
| `ci` | 持续集成配置 |
| `style` | 不改变行为的格式调整 |
| `chore` | 其他维护工作 |
| `revert` | 撤销已有变更 |

`scope` 按实际影响选择，如 `script`、`map`、`sql`、`release`，没有合适范围时可省略。破坏兼容性的变更使用 `!` 或 `BREAKING CHANGE:` footer，并说明影响和迁移方法。

```text
fix(script): 恢复鉴定事件的脚本常量导出
feat(map): 支持新的地图规则
docs: 建立仓库开发规范
fix(release): 从运行包排除开发文档
```

## 提交边界与说明

一个提交表达一个可独立理解和验证的改动；无关整理和行为修复分开。标题描述最终结果。正文按需要说明触发条件、根因、行为变化和验证结果；关联上游或历史修复时提供提交号，方便追溯。

提交前检查暂存 diff，避免夹带本地编译试验、生成制品、私人配置或无关文件。确认用户已授权 commit；后续 push、merge、release 分别按其授权范围执行。遵守现有签名与 hook 配置，遇到失败先排查原因。
