# 上游同步规范

同步目标是吸收选定 rAthena 版本的更新，同时保留 Pandas 的功能边界、数据处理和已有修复。此次开发文档建立时，对照基线为 rAthena `67431ee25c641a1064b07365f8a916cd26678fca`：适配提交 `81987167a4` 的第二父即该提交，`6328ac345c` 汇总这一轮同步。

## 同步 PR 与汇总合并

rAthena 同步使用当前仓库的 `merge_rathena` 分支，按协作需要向 `develop` 创建 PR。同步合入需保留 merge commit，保存 rAthena 历史、适配提交和目标分支之间的合并关系；通过 PR 合入时选择 **Create a merge commit**（`gh pr merge --merge`），此类同步不使用 Rebase and merge 或 Squash and merge。本地合并后直接推送时，也须保留该合并关系，并确保远端 `develop` 能快进到目标提交。

汇总 merge commit 第一行标题使用以下格式；采用 PR 时，PR 标题与其一致：

```text
汇总合并 rAthena 官方最新代码 - YYYY年MM月DD日
```

使用 `rAthena` 的原有大小写、半角连字符及其两侧空格，月份和日期补齐两位，标题末尾不加句号。日期采用本轮同步批次确定的日期，实际合入时保留该日期，不自动替换为合入当天。合并时显式填写这一标题，避免使用 GitHub 默认的 `Merge pull request #...` 标题；通过 `gh pr merge` 操作时使用 `--subject` 指定。

这一专用标题是 [提交规范](commits.md) 中 Conventional Commits 格式的例外；普通改动的 PR 默认使用 Rebase and merge。

## 建立比较基线

开始前核对远端身份、目标分支、工作区和已有合并关系，记录本轮 Pandas 起点、上次上游基点及本次上游目标的完整 SHA。使用确定的提交做比较，分支名只用于定位。

对需要审查的路径同时比较四份内容：上次上游版本、合并前 Pandas、本次上游目标、合并结果。先用 `Pandas_*` 宏和注释定位差异，意图仍不清楚时通过 `git log -p -- <路径>`、`git blame` 和相关提交补充历史。

```sh
git diff <上次上游SHA> <本次上游SHA> -- <路径>
git diff <上次上游SHA> <合并前PandasSHA> -- <路径>
git diff <本次上游SHA> <合并结果SHA> -- <路径>
```

## 合并时保留什么

| 情况 | 处理 |
| --- | --- |
| 上游新增或修正的逻辑 | 吸收实现，并补齐 Pandas 环境中的入口、注册、宏和数据适配 |
| Pandas 自有功能 | 保留原有意图，按新接口调整，核对启停路径 |
| Pandas 以前已修复、合并后重新出现的问题 | 恢复等效修复；上游已有部分修复时比较完整保护条件和结果 |
| 上游主动移除或改变了相似逻辑 | 查清对应提交、调用前提和设计原因，再判断 Pandas 是否仍需保留 |
| 本轮新发现、此前也存在的上游问题 | 记录证据和影响，按任务范围决定后续处理 |

判断“上游后来也删过”必须追溯该路径的历史及上下文，不能只看当前差异。判断本地修复是否被上游吸收，应比较输入范围、检查顺序、资源清理和输出行为。

## 重点联动检查

1. **宏和外部入口**：声明、实现、注册表、脚本常量导出、配置、调用方是否成套存在。`1186cd0709` 补回鉴定事件脚本常量导出，是实现与导出需要一起检查的历史例子。
2. **类型与生命周期**：上游类型、符号性或所有权变化后，核对边界检查、整数运算、删除顺序和释放后访问。
3. **数据覆盖**：YAML 版本及字段变化是否传播到 `db/pandas/`、模板和用户覆盖路径，加载优先级是否保持。
4. **SQL 与升级**：新建库 SQL、日期型上游升级和 Pandas 版本汇总升级是否表达一致的最终 schema；覆盖 `main`、`logs`、`web` 及可选 `use_sql_db` 用法。
5. **开发与发布设施**：检查构建工程、依赖、`PYHELP` 标记、翻译字典、发行覆盖树和 SQL 目录重排，参考 [发布流程](../architecture/release-pipeline.md)。

## 验证与交付

先确认冲突解决的语义，再执行受影响的编译组合、数据加载和回归场景。复现曾丢失的修复时，验证触发条件和完整行为，不只检查宏或某行代码存在。

审查结论列明比较基点、保留的本地差异、修复及验证。同步过程中发现的独立问题与必要适配分开说明。新编写的修复提交遵循 [提交规范](commits.md)，保留导入的上游提交历史。
